# Stage 3: Mock Interview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A timed mock interview: 25 mixed questions in 30 minutes with no feedback while it runs, a result broken down by topic that never shows the correct answers, and the missed questions sent straight to the "Xatolar" session.

**Architecture:** `MockSession` and the mock question pick are pure Kotlin in `:core:engine`. `:app` adds a view model with a deadline-based countdown, a mock screen, a result screen, and one repository call that stores the session, the per-topic scores and the Leitner updates in a single transaction.

**Tech Stack:** unchanged from Stage 2.

**Spec:** `docs/superpowers/specs/2026-10-02-devsuhbat-design.md` (sections 5.3, 6, 7.4, 8).

## Global Constraints

- Mock size 25, duration 30 minutes. About 60% of the questions are of the chosen level and 40% of lower levels; Junior is all Junior.
- Fewer than 25 eligible questions: the mock runs with what there is. Fewer than 5: the mock cannot be started.
- One answer per question, changeable until the mock is finished. No feedback during the mock.
- An unanswered question counts as wrong.
- The result shows total, correct, and per-topic `correct / total`. It never shows which option was correct.
- A wrong (or unanswered) question becomes box 1 with `dueDay = today`, so it is in "Xatolar" at once. A correct one is treated as "first try correct" (Stage 2 rules).
- When the time runs out the mock finishes by itself with the answers given so far.
- A question's topic is its id without the last segment: `android.kotlin.001` → `android.kotlin`.
- Room stays at version 1; `mock_topic_result` already exists.
- Leaving the mock (back, close) asks for confirmation and stores nothing.

## Review Focus

1. The clock keeps running while the app is in the background: the remaining time comes from a deadline, not from counting ticks. Test in Task 3 (`remainingTimeFollowsTheClockNotTheTicks`).
2. Finishing twice (the user taps "Yakunlash" as the timer fires) must store one result. Test in Task 3 (`finishIsReportedOnce`).
3. A topic with questions in the mock but none answered correctly must still appear in the per-topic list with `0 / n`. Test in Task 1 (`finishScoresAnswers`).
4. A field with 5 to 24 eligible questions gets a shorter mock, not a crash or a padded one. Test in Task 1 (`mockReturnsAllWhenThePoolIsSmall`).
5. A failed mock question must be due today, not tomorrow. Test in Task 1 (`afterMockWrongIsDueToday`) and Task 2 (`recordMockSendsMissedQuestionsToToday`).

### Task 3: MockViewModel

**Files:**
- Create: `app/src/main/java/uz/devsuhbat/ui/mock/MockViewModel.kt`
- Test: `app/src/test/java/uz/devsuhbat/ui/mock/MockViewModelTest.kt`

**Interfaces:**

```kotlin
data class MockSetup(val questions: List<Question>, val topicTitles: Map<String, String>)
data class MockUiState(
    val loading: Boolean = true,
    val question: Question? = null, val index: Int = 0, val size: Int = 0,
    val selected: Set<String> = emptySet(),
    val answered: Set<Int> = emptySet(),            // indices that have an answer
    val remainingSeconds: Int = 0,
    val result: MockResult? = null,
    val topicTitles: Map<String, String> = emptyMap(),
)
class MockViewModel(
    private val load: suspend () -> MockSetup,
    private val random: Random,
    private val now: () -> Long,                     // milliseconds
    private val onFinished: suspend (MockResult) -> Unit = {},
    private val durationSeconds: Int = DURATION_SECONDS,   // 30 * 60
) : ViewModel() {
    val state: StateFlow<MockUiState>
    fun toggle(optionId: String)                     // SINGLE: replace (tapping the selected option clears it); MULTI: toggle
    fun goTo(index: Int); fun next(); fun previous()
    fun finish()
}
```

The deadline is `now() + durationSeconds * 1000` taken when the questions are loaded. A coroutine wakes every second, sets `remainingSeconds = ceil((deadline - now()) / 1000)` clamped at 0, and calls `finish()` at 0. An empty setup produces a result with `total == 0` at once and reports nothing. `onFinished` is called once.
